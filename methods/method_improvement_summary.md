# CASU 方法改进方案：成对上下文参考与生成反馈驱动的选择性更新

更新日期：2026-10-14。

本文汇总目前讨论形成的研究方案。保留原论文的动机和 Closed-form Solution with Null Space Constraint，修改编辑接口、Contextual Anchor（CA）与 Selective Update。以下是方法设计，尚未运行真实扩散模型实验。

**本版采用最新确定的选择规则：先启用全部候选模块的闭式更新，每轮撤去一个模块的更新并生成图像，由多模态大模型判断目标是否重新出现；首次出现时撤销该轮删除，返回上一轮模型并停止。** 此规则取代此前讨论的“代理约束作为停止条件”以及“删除失败后继续尝试其他模块”。低成本代理可以用于安排删除顺序，但不负责决定本版是否停止。

## 1. 保留的动机与整体变化

原论文的两个动机继续保留：

1. 将目标概念重定向到 null/generic anchor 可能引起明显的图像语义变化，损伤目标之外的场景、对象或结构。
2. 对所有候选注意力层统一施加更新可能造成不必要的干预，需要保留足以完成擦除的更新。

迁移到不同架构后，第二点更一般地表述为：**对全部文本条件注入模块统一更新可能造成过度修改，因此需要选择必要的条件通路或模块。**

| 项目 | 原方法 | 本版方案 |
| --- | --- | --- |
| 闭式求解 | 带保留概念零空间约束的参数更新 | 保留相同的目标函数和闭式求解形式 |
| 编辑对象 | U-Net cross-attention 的 K/V | 各模型实际的文本条件注入线性模块 |
| 求解表示 | 固定文本 encoder 中的概念表示 | 每个模型、每个模块实际接收的输入表示 |
| CA | LLM 生成模板，再对表示求平均 | 多组同场景的目标—替代提示及其逐模块配对表示 |
| Selective Update | 固定区间内的目标—anchor attention map 差值，固定 Top-K | 全部候选先编辑，按顺序逐个撤去更新，用生成结果和多模态判别决定停止 |
| 共享参数处理 | 默认编辑投影权重 | 文本专用模块直接合并权重；共享模块只对文本 token 施加纠正 |
| 迁移方式 | 依赖特定 cross-attention 接口 | 共享构造与求解流程，分别定位模块、提取表示和校准 |

原固定探测区间、attention map 大小差值以及固定更新比例不再作为方法组成。

## 2. 编辑入口：不同模型的文本条件注入模块

### 2.1 统一选择原则

编辑单元是一个线性模块，或预先规定的一组线性模块。优先选择：

- 接收文本序列 hidden states 的专用投影。
- 接收 pooled 文本表示的专用线性层。
- 文本流进入注意力的专用 K/V 投影。

“全部模块更新”是指**预先定义的全部候选文本条件模块**，不是整个生成模型中的所有线性层。图像输入投影、时间分支和其他非文本模块不自动加入候选集合。

模块清单、分组方式和数量 $n$ 必须在实验前固定。同一注意力的 K/V 可以分别作为单元，也可以作为一组；分组后，一次删除必须同时撤去组内全部更新，不能在不同实验中混用计数规则。

### 2.2 SD、SDXL、SD3 与 FLUX 的候选入口

以下以常见 SD1.x/2.x、SDXL base、SD3 和 FLUX.1 的实现为参照。具体 checkpoint、实现版本以及 QKV 融合方式仍需在实验中记录。

| 模型 | 文本条件通路 | 优先候选模块 | 需要处理的特点 |
| --- | --- | --- | --- |
| SD1.x / SD2.x | CLIP/OpenCLIP 的 token hidden states 注入 U-Net cross-attention | 各 cross-attention 的 attn2.to_k、attn2.to_v | 这些 K/V 接受文本条件；通常不能假定另有一个统一、独立的输入投影 |
| SDXL base | 两个文本 encoder 的 token 表示拼接后注入 cross-attention；另有 pooled 文本附加条件 | attn2.to_k、attn2.to_v；附加条件入口 add_embedding.linear_1 的文本输入列 | pooled 文本与尺寸/裁剪等 time_ids 编码一起拼接；应只更新文本部分，保留元数据部分 |
| SD3 | token 条件经 context_embedder 进入 MMDiT；pooled 文本经 time_text_embed.text_embedder 注入；block 中还有文本专用 QKV | transformer.context_embedder；time_text_embed.text_embedder.linear_1 / linear_2；扩展实验可加入 block.attn.add_k_proj / add_v_proj | token 与 pooled 是不同通路，应分别提取与求解；block 内文本状态受到时间条件和图像交互影响 |
| FLUX.1 | token 条件入口与 pooled 文本分支；double-stream block 有文本专用 QKV；single-stream block 共享映射 | 官方实现的 txt_in、vector_in 内线性层；Diffusers 对应 context_embedder、time_text_embed.text_embedder；扩展实验可加入 double-stream 文本 K/V | single-stream 的共享投影若纳入，必须使用文本 token 条件纠正，不能直接整体改写共享权重 |

SD/SDXL 的 K/V 输入与 SDXL 附加条件拼接可参考 [Diffusers attention 实现](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/attention_processor.py) 和 [U-Net 实现](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/unets/unet_2d_condition.py)。SD3、FLUX 的入口分别见 [SD3 Transformer](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_sd3.py)、[FLUX Transformer](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/transformers/transformer_flux.py) 及 [FLUX 官方实现](https://github.com/black-forest-labs/flux/blob/main/src/flux/model.py)；pooled 文本分支的线性层见 [Diffusers embeddings](https://github.com/huggingface/diffusers/blob/main/src/diffusers/models/embeddings.py)。

实施时还应注意：

1. SDXL 的 add_embedding.linear_1 可写成 $W=[W_{\mathrm{text}},W_{\mathrm{meta}}]$。第一版只求解 $W_{\mathrm{text}}$ 的更新，令元数据列更新为零。其第二层输入已混合文本、元数据和非线性变换，第一版不默认纳入。
2. 对 text_embedder/vector_in 这类 MLP，只把其中一个线性层作为 $W_m$。编辑第二层时，输入应是第一层和激活函数之后的实际表示，不能把整个 MLP 当作一个线性矩阵。
3. 多条文本通路可能同时携带目标。不能默认只处理 token 通路或只处理 pooled 通路就完成擦除；需要通过通路消融确认。
4. text-to-image cross-attention 中的 Q 通常来自图像状态。第一版优先 K/V；文本专用 Q 可作为后续扩展，不把图像 Q 自动纳入文本编辑。

## 3. CA 改进：成对上下文参考

### 3.1 提示对的构造

设目标概念为 $c$，替代概念或描述为 $a$，非目标场景为 $s_i$。构造：

$$
p_i^T=\operatorname{Prompt}(c,s_i),
\qquad
p_i^A=\operatorname{Prompt}(a,s_i).
$$

一对提示只改变擦除相关部分，其余场景、动作、对象属性和关系尽量一致。

例如，擦除特定角色时：

| 目标提示 | 替代提示 | 保留的上下文 |
| --- | --- | --- |
| In a sunny park, Snoopy is running beside a red bicycle. | In a sunny park, an ordinary dog is running beside a red bicycle. | 公园、晴天、奔跑、自行车、红色、相邻关系 |
| On a beach at sunset, Snoopy is sitting near a blue umbrella. | On a beach at sunset, an ordinary dog is sitting near a blue umbrella. | 海滩、日落、坐姿、蓝色遮阳伞、相邻关系 |

示例中的替代描述只是候选，不能假定其一定安全。上位类别或相似描述仍可能诱发目标，需要检验生成结果。风格擦除应保持场景，改变风格描述；目标特有的关联物、标志性属性也需判断是否属于擦除范围。

### 3.2 为什么它包含 contextual 信息？

上下文来自三个环节：

**第一，提示对在语义层保持相同场景。** 参考不是孤立的“dog”或空文本，而是“同一公园里、同一动作和其他对象关系下的普通狗”。闭式编辑的期望输出因此包含应保留的非目标内容。

**第二，使用该场景下的实际表示。** 同一概念在不同提示中的 hidden states 可以不同；深层文本状态还可能依赖当前 latent 和 timestep。成对参考在这些条件相匹配时提取，而不是把所有场景压缩成一个通用均值。

**第三，保留逐样本对应关系。** 公园中的目标表示对应公园中的替代表示，海滩中的目标表示对应海滩中的替代表示：

$$
x_{m,i}^{T}\longrightarrow y_{m,i}^{A}.
$$

多个场景作为不同拟合样本进入闭式解。因此，方法学习的是多个上下文条件下的重定向关系。

不过，**成对提示具有上下文，不代表任意抽取的 token 都包含全部上下文。** 特别是 CLIP 使用 causal text attention：只抽取位于句首的目标词 token，不能假定它读到了后面的场景描述。参见 [CLIP 官方文本 attention mask 实现](https://github.com/openai/CLIP/blob/main/clip/model.py)。

为实际利用上下文，建议：

- 保留模块接收的完整文本序列，并选择规则明确的配对 token 样本。
- 在只提取目标 span 的消融中，把必要场景放在目标前，并检查编码器的 attention mask。
- pooled 分支使用该模块真实接收的 pooled 表示；不能用它替代 token 分支的输入。
- 对深层模块，提取其真实文本状态，不复用 encoder 输出假装是深层输入。

上述设计提供上下文保持的监督，但不构成最终图像布局完全不变的保证。

### 3.3 token 对齐与多场景矩阵

对每一提示对，在各模块分别构造 $X_T^{(m)}$ 与 $X_A^{(m)}$。二者列数一致，每一列的对应规则明确。

token 序列对齐至少需要处理：目标与替代 span 长度不同、未修改词的位置移动、EOS、padding 和有效 attention mask。未修改跨度按词或跨度对应；长度不同的目标跨度可预先规定匹配/重采样规则。拟合源列应来自实际模块输入，不能未经说明把均值表示当成模型运行时真的接收的 token。

第一版固定 token 提取和对齐规则，控制每个场景的样本数量，避免长提示因列数更多而获得更大的隐含权重。

特别需要避免：给同一个、完全不随场景变化的源向量 $c$ 配上多个参考 $a_i$。在最小二乘目标下，这仍主要等价于映射到参考均值：

$$
\sum_i\|(W+\Delta W)c-Wa_i\|^2
=K\|(W+\Delta W)c-W\bar a\|^2+\text{常数}.
$$

因此，本版同时使用**不同上下文产生的源表示**与对应参考，而不只增加 anchor 数量。

### 3.4 anchor 候选与校准

anchor 可以来自固定人工词表、类别表或模板，也可以由 LLM 辅助生成。方法的核心不再依赖 LLM 模板均值。

每种替代策略构成一组完整提示对；各模型和模块分别提取表示。先固定候选模块集合，比较少量替代策略的实际编辑结果，选择目标抑制充分且内容损伤较小的一组，再固定 anchor 搜索模块。

“校准”指把 anchor 放入原闭式求解器后，评价**编辑模型收到目标提示时**的表现。仅证明原模型收到替代提示不生成目标，并不足以证明编辑有效。正则化、零空间限制和多目标耦合都可能造成重定向残差。

第一版采用有限候选选择，不引入高维 anchor 梯度优化。若后续沿固定目标—anchor 方向做插值，应加入更新强度缩放对照：在单目标、其他条件固定时，这类插值通常只是缩放同一个闭式更新。

## 4. 从提示到模块输入/输出，以及闭式解公式

### 4.1 明确“target prompt → 中间层输出”的含义

含 target 的提示首先经过原模型，得到候选模块的输入与输出；替代提示经过同一原模型，得到对应参考：

$$
p_i^T
\longrightarrow h_m^0(x_{t_i},t_i,p_i^T)
\longrightarrow y_{m,i}^{T,0},
$$

$$
p_i^A
\longrightarrow h_m^0(x_{t_i},t_i,p_i^A)
\longrightarrow y_{m,i}^{A,0}.
$$

编辑希望实现：

$$
\boxed{
\text{目标提示的模块实际输入}
\longrightarrow
\text{替代提示在原模型中的同一模块输出}
}
$$

目标提示的原始中间输出用于计算编辑前基线；它不是擦除拟合的期望输出。若只要求“目标输入对齐其原始目标输出”，不产生目标到 anchor 的重定向。

### 4.2 逐模块数据定义

候选模块 $m$ 是线性映射：

$$
y=W_mh+b_m,
\qquad
W_m\in\mathbb R^{d_{\mathrm{out}}\times d_{\mathrm{in}}}.
$$

在原模型中提取：

$$
x_{m,i}^T=h_m^0(x_{t_i},t_i,p_i^T),
\qquad
x_{m,i}^A=h_m^0(x_{t_i},t_i,p_i^A).
$$

为目标与替代运行使用相同的 $x_{t_i}$、$t_i$ 和相关非文本条件。不能把两条独立采样轨迹在相同 step 的状态直接当成局部匹配输入。

堆叠为：

$$
X_T^{(m)}=[x_{m,1}^T,\ldots,x_{m,N}^T],
\qquad
X_A^{(m)}=[x_{m,1}^A,\ldots,x_{m,N}^A].
$$

参考输出为：

$$
Y_A^{(m)}=W_mX_A^{(m)}+b_m\mathbf 1^\top.
$$

由独立保留提示提取该模块输入，构造 $X_P^{(m)}$。每个模块维度和坐标系分别处理；迁移时重新提取和求解，不跨架构复用同一个数值 anchor 或参数补丁。

若模块输入先经过归一化、调制或非线性，应捕获这些操作之后、该线性层之前的实际输入。对于纯文本入口，输入可能不依赖 $x_t,t$，此时不必重复相同表示来增加样本数。

### 4.3 零空间约束

设 $U_m$ 的列是 $X_P^{(m)}$ 列空间的一组正交归一基，可由 SVD 或 QR 获得，构造：

$$
P_m=I-U_mU_m^\top,
\qquad
P_mX_P^{(m)}=0.
$$

令实际权重更新为 $\Delta W_m=D_mP_m$，因此：

$$
\Delta W_mX_P^{(m)}=0.
$$

该约束保证的是**指定保留输入上的这个线性映射不变**。多模块联合更新后，下游输入可能改变；不能将它扩大为全部非目标生成结果都不变。数值截断若放松了保护子空间，也需要单独说明。

### 4.4 保留原目标函数与闭式解

完整目标为：

$$
\min_{D_m}
\left\|
(W_m+D_mP_m)X_T^{(m)}
+b_m\mathbf 1^\top-Y_A^{(m)}
\right\|_F^2
+\beta\|D_mP_m\|_F^2.
$$

固定 bias 后，代入 $Y_A^{(m)}$，它等价于：

$$
\min_{D_m}
\left\|
(W_m+D_mP_m)X_T^{(m)}
-W_mX_A^{(m)}
\right\|_F^2
+\beta\|D_mP_m\|_F^2.
$$

这与原论文公式形式一致，只把固定概念 embedding 换成模块实际输入：

$$
\boxed{
\Delta W_m=
W_m(X_A^{(m)}-X_T^{(m)})
(X_T^{(m)})^\top P_m
\left(
X_T^{(m)}(X_T^{(m)})^\top P_m+\beta I
\right)^{-1}
}
$$

其中 $\beta>0$。一个等价的样本维度写法是：

$$
\Delta W_m=
W_m(X_A^{(m)}-X_T^{(m)})
\left(
(X_T^{(m)})^\top P_mX_T^{(m)}+\beta I_N
\right)^{-1}
(X_T^{(m)})^\top P_m.
$$

实现时根据输入维度与样本数选择较小的线性系统，使用求解器而非显式构造逆矩阵。多目标样本进入同一个模块的联合矩阵，不能简单相加各目标独立求出的更新。

若 $P_mX_T^{(m)}=0$，这类保护约束下没有可改变目标的方向；换 anchor 本身不能解决可达性问题。

## 5. 只作用于文本条件的部署方式

### 5.1 文本专用模块

直接合并：

$$
W_m^{\mathrm{edit}}=W_m+\Delta W_m.
$$

pooled 文本分支也属于文本条件编辑，虽然它不是 token 序列。SDXL 混合入口只合并文本输入列的更新。

### 5.2 文本与图像共享的投影

使用模态条件纠正：

$$
y_i=W_mh_i+b_m
+\mathbf 1[i\in\mathcal T]\Delta W_mh_i,
$$

其中 $\mathcal T$ 是文本 token 索引集合。图像 token 继续使用原共享映射。该 mask 根据模态位置确定，不依赖输入是否显式出现目标名称。

这类纠正通常不能折叠成一个对所有 token 共享的新矩阵，可用低秩分解保留运行期补丁，并报告额外时间、显存和模型结构变化。若做输入侧算子，只有在接口与相邻线性映射允许时才能等价合并；不能跨越归一化或非线性随意折叠。

只作用于文本 token 减少对共享图像映射的直接修改，但文本变化仍会经注意力影响图像生成，因此最终保留能力仍需验证。

## 6. Selective Update：全部编辑后逐模块撤去更新

### 6.1 固定候选更新

令候选集合为 $\mathcal M=\{1,\ldots,n\}$。用已固定的 anchor 和保护集合，分别求得 $\Delta W_m$。

对集合 $S$：

$$
W_m(S)=W_m+\mathbf 1[m\in S]\Delta W_m.
$$

共享模块采用上一节的文本条件部署式。

先启用全部候选更新，$S_0=\mathcal M$。每次“删除模块”只撤去该模块的编辑，将其恢复为原权重/原映射；**不删除原模型的网络模块**。每个试验都由同一原模型加当前 mask 构造，不能累积施加同一个补丁。

第一版搜索期间固定所有候选更新，不逐轮重收集激活和重新求解。联合输入变化会影响效果，由实际生成检验；重估更新可作为后续独立扩展。

### 6.2 每轮选择哪个模块？

首次失败即停止的规则对删除顺序敏感，因此需要提前规定顺序。第一版建议使用一次低成本评分：

1. 在覆盖整个采样过程的少量匹配 latent/timestep 上，比较当前全更新组合与撤去每个模块后的模型预测。
2. 优先撤去目标重定向误差上升较小的模块。
3. 擦除影响接近时，优先撤去非目标响应损伤减少较多的模块；再以干预参数量作为次级排序依据。
4. 将顺序固定为 $\pi=(m_1,\ldots,m_n)$，后续每轮仅按顺序尝试一个模块。

可使用：

$$
E_{T,c}(S)=
\mathbb E_{i\in c}
\frac{
\|f_S(x_{t_i},t_i,p_i^T)-f_0(x_{t_i},t_i,p_i^A)\|^2
}{
\|f_0(x_{t_i},t_i,p_i^T)-f_0(x_{t_i},t_i,p_i^A)\|^2+\epsilon
},
$$

$$
D_N(S)=
\mathbb E_j
\|f_S(x_{t_j},t_j,p_j^N)-f_0(x_{t_j},t_j,p_j^N)\|^2.
$$

其中 $f$ 是该模型原生的预测输出；参考模型 $f_0$ 冻结。弱对比提示对需剔除或降低权重。多目标排序应考虑各目标误差变化，避免只看总体平均。

这些代理**只决定删除顺序**，不作为本版擦除成功或停止的判据。时间步抽样用于覆盖响应，不恢复原 attention 固定区间指标。需要为每个 mask 重新执行网络前向，不能简单叠加缓存的单层输出差异代替组合响应。

也可把固定架构顺序、随机顺序作为对照。若每轮重新对全部剩余模块排名，成本会升为最坏 $O(n^2)$ 次代理评价，第一版不采用。

### 6.3 多模态大模型作为停止判据

对每个候选集合 $S$，在固定评价提示与 seed 上完整生成：

$$
I_i(S)=\operatorname{Generate}(\theta(S),p_i,z_i).
$$

多模态判别器 $V$ 根据明确的目标定义判断：

$$
v_{c,i}(S)=
\begin{cases}
1,&\text{图像含目标概念 }c,\\
0,&\text{图像不含目标概念 }c.
\end{cases}
$$

本版按“任一校准样本重新生成目标就停止”的严格规则：

$$
\operatorname{Reappear}(S)
=\max_{c,i}v_{c,i}(S).
$$

先检查 $S_0$。若全部候选更新后已检出目标，则初始组合未达擦除要求，应检查 anchor、可编辑方向和条件通路；不能直接进入一个以“成功擦除”为起点的删除过程。

第 $k$ 轮：

$$
S'=S_{k-1}\setminus\{m_k\}.
$$

- 若 $\operatorname{Reappear}(S')=0$：接受删除，令 $S_k=S'$，继续下一轮。
- 若 $\operatorname{Reappear}(S')=1$：撤销该轮删除，返回 $S_{k-1}$，停止整个迭代。

**最终模型是最后一个未检出目标的集合，不是首次失败后的集合。** 多目标时，任何一个目标重新出现都触发停止。

判别器可以输出“无法判断”。这一情况不能当作“不含目标”接受删除，应按预先规定的复核流程处理；若仍不确定，保留上一轮模型并记录不确定性。

### 6.4 伪代码

~~~text
输入：原模型 θ0，候选集合 M，固定补丁 ΔW，
      删除顺序 π，固定校准提示和 seed，多模态判别器 V

S ← M
生成 θ0 + mask(S)·ΔW 的校准图像
若检出任一目标：
    返回“全更新初始组合未达到擦除要求”

对 m 按 π 的顺序：
    S_trial ← S \ {m}
    从 θ0 与固定 ΔW 构造 trial 模型
    生成固定校准图像
    用 V 判别全部目标

    若任一图像中目标重新出现：
        返回 S 对应模型
    若无法确定且复核仍未解决：
        返回 S 对应模型，并记录原因

    S ← S_trial
    记录目标判断、内容保留和剩余干预量

返回 S 对应模型
~~~

若所有模块均可撤去却仍未检出目标，需要复查校准提示和判别器是否有辨别力；原模型必须先能在足够样本上生成所测目标。

### 6.5 这一停止规则能说明什么？

首次失败说明：**在当前已接受的删除、当前顺序与校准数据下，再撤去本次模块更新会导致目标重新出现。**

它不能说明其他剩余模块都必要，也不保证全局最小模块集合。其他顺序、成对删除或交换可能得到不同结果。这是本版启发式搜索的限制，应通过随机顺序和不同排序策略的实验分析。

## 7. 多模态评价：目标残留与内容保留

### 7.1 目标判别协议

固定多模态模型版本、目标定义、提问模板和推理设置。明确普通对象、角色身份、艺术风格等不同目标的边界；角色相似物与原角色、内容对象与艺术风格不能混为一类。

判别器按固定格式输出“存在/不存在/无法确定”及简短视觉依据。目标判断应根据图片进行，避免仅因为生成提示中出现目标名称就判为存在。可以提供目标定义或少量参考图，但不向判别器暴露候选方法名称。

校准集包含多种场景、多个 seed、直接命名和间接描述。最终测试提示与 seed 独立于 anchor 选择和模块删除。

不把语言模型自报置信度自动视为经过校准的概率。用小规模人工标注集检查误报、漏报以及风格/角色识别能力。

### 7.2 内容保留

内容保留分两部分：

1. **目标提示中的剩余内容**：把提示拆成对象、属性、动作、背景和关系检查项，排除本应被移除的目标属性；多模态模型判断是否保留。
2. **非目标提示的生成能力**：独立保护提示上评价语义符合、质量和明显变化；结合模型响应漂移等低成本辅助指标。

原图与编辑图采用相同生成设置及 seed，允许应擦除部分发生变化。不能要求风格擦除前后颜色、纹理或笔触完全相同；对依赖目标身份的关系，也需修改评价定义。

内容保留可以辅助选择 anchor、安排删除顺序，并记录每轮结果。**本版全局停止条件仍是目标重新出现，不另加内容保留阈值来改写用户确定的流程。** 更少更新是否真的减少损伤需要实测，不能仅由模块数量下降推出。

## 8. 完整流程与计算成本

### 8.1 完整流程

1. 为目标构造多场景的目标—替代提示对，并确定独立保留提示。
2. 为各架构定位 token 条件、pooled 条件和可选文本专用 block 模块。
3. 在原模型中收集逐模块的实际输入及参考输出；深层对照匹配 latent/timestep。
4. 构造各模块的保护零空间，求解固定闭式更新。
5. 若有多个 anchor 策略，先在固定模块集合下比较并选定，再固定 anchor。
6. 启用全部候选更新，生成并检查初始组合。
7. 确定删除顺序，每轮撤去一个补丁并生成，多模态判别首次检出目标时回退并停止。
8. 部署最后一个成功组合，在独立测试集验证目标残留、内容保留和成本。

### 8.2 复杂度

若顺序固定，最多执行 $n$ 次删除试验，加一次全更新初始检查，因此需要评价至多 $n+1$ 个组合，不是 $2^n$ 个。

设每组合生成 $G$ 张图像，每张有 $T$ 次骨干模型调用，多模态逐图判断成本为 $C_V$，生成骨干单次调用成本为 $C_f$，主要搜索成本为：

$$
O\big((n+1)G(TC_f+C_V)\big).
$$

排序若使用 $B$ 个缓存状态做一次逐模块撤去评价，另增加约 $O(nBC_f)$；还需计入最初的表示提取、闭式求解及 anchor 候选成本。

**本版以线性的组合数量换取实际生成反馈，但每轮完整采样和多模态判断仍可能昂贵。** 这与此前主要靠代理搜索、仅最后少量生成的版本不同，实验中应报告整个选择阶段的真实耗时和调用量。

固定所有轮次的校准提示、seed、采样器、步数及 guidance 设置，减少候选间的评估波动。最终独立测试检查是否过拟合这些固定条件。

## 9. 实验应隔离的贡献与限制

### 9.1 CA 对照

固定编辑入口、候选集合、求解器和样本预算，比较：

- null/generic anchor。
- 原 LLM 模板均值 anchor。
- 成对提示表示。
- 成对提示加实际编辑结果的候选校准。

分别比较目标 span、对齐序列和真实 pooled 通路，检验上下文信息是否真正进入拟合，而非只存在于提示文字中。连续强度调整需与直接缩放补丁或调整正则强度对照。

### 9.2 Selective Update 对照

固定 anchor 和候选补丁，比较：

- 全模块更新。
- 原 AGSU（适用的 U-Net 设置）。
- 随机顺序、固定架构顺序和代理排序的首次失败停止。
- 多个随机顺序，观察删除顺序的影响。

相同擦除水平下报告内容保留、编辑参数量、更新规模、选择耗时和多模态判别调用量。跨架构比较共享的是流程，不要求使用同一模块名称或同一数值补丁。

### 9.3 研究定位

闭式擦除迁移到 DiT、文本条件入口编辑、激活子空间构造已有先例；本地相关工作见 [闭式 DiT 文献检索报告](/home/shx/code/ce-new/papers/CLOSED_FORM_DIT_SEARCH.md)。

后续贡献需要通过实验具体建立在：成对实际表示如何改善上下文重定向、生成反馈选择如何减少过度修改，以及它们在不同条件通路中的一致性和总成本。不能仅以“使用成对提示”“支持 DiT”或“贪心删除”本身证明新颖性。

## 10. 可用于后续方法写作的概括

本方法面向文本条件驱动的扩散模型概念擦除，在各架构的文本条件注入线性模块上构造闭式编辑。通过保持非目标场景一致的目标—替代提示对，分别提取每个模块的真实输入，将目标条件对应的模块输出重定向到同场景替代条件的参考输出，并在保留输入的零空间内约束权重更新。随后从全部候选更新出发，按照预定顺序逐个撤去编辑，以实际生成图像和多模态目标判别作为反馈；首次检测到目标重新出现时恢复该次更新并停止，得到当前删除路径下最后一个通过擦除检查的组合。文本专用更新直接合并进权重，共享投影中的更新仅作用于文本 token。
