# 最小验证、对照与论文实验计划

日期：2026-10-26。对应 [重噪自检的速度擦除](README.zh-CN.md)。以下全部为待执行计划，不包含实测成绩。

## 1. 第一阶段只回答“分数是否值得使用”

先在一个原生 FM DiT 上做离线诊断。优先 SD3.5-medium，以便区分原始条件 velocity 与 CFG；随后在 FLUX.1-dev 上检查 guidance-distilled 模型是否还能使用同样信号。先做两模型的小规模诊断，再决定哪一个作为完整 benchmark 主模型。

### 1.1 一个明确的小规模数据安排

先选两个容易人工判别的对象概念、一个风格概念。对象候选可以从 DVE 已用的 `church`、`English springer` 等开始，但必须确认原模型有足够的生成成功率。

每概念先用 48 个提示、各 2 个固定种子，共 96 个原生成端点。提示分四组，各 12 个：

| 组别 | 作用 |
| --- | --- |
| 显式目标提示 | 检查基本可擦除性 |
| 隐式目标描述 | 避免仅测“有没有目标词” |
| 安全近邻概念 | 测误伤，如其他建筑、其他犬种 |
| 无关场景 | 测普遍施加纠正的副作用 |

按提示模板分为 24 个开发提示和 24 个测试提示，每组各占一半；不能只拆种子而复用同模板。这个规模用于快速诊断，不作为最终论文的统计充分性承诺。

另固定一组构造方向的 `f/a` 模板、一组在线 `f_probe/a_probe` 模板和一组离线审核模板。模板都由人工定义；不在线调用 LLM。开发集与测试集不共享完整测试句式。

### 1.2 必须标注真实图像，而不是把提示当标签

人工检查原生成端点，记录目标是否存在、主体是否完整、其他对象是否存在。原提示要求生成目标，但模型实际没生成，不能标成“目标存在”。可使用现成离线评测器帮助整理，但人工抽查保留为独立依据。

先对完整端点 latent 重噪，测试内部分数；这一步排除 clean estimate 不准的影响。然后再对中间状态的 clean estimate 重复检查。

至少记录：目标/非目标区分 AUROC、开发集选定阈值对应的测试假阳性率与召回、不同噪声种子下的一致性。不要只报告均值分数差。

### 1.3 更关键的诊断：能不能在候选之间排序

从每概念测试部分预先取 12 个提示，各 2 个种子，每条轨迹取前、中、后三个状态；在这些状态离线构造两个候选。

每个候选正常走完剩余生成过程，得到真实终点。这些完整 rollout 仅用于研究标签，**不计成部署算法的一部分，也不能不计为研究成本**。

对每一对候选记录：

- 内部评分更偏好哪一个；
- 最终目标存在与否，以及残留强弱；
- 目标以外的主体、关系、背景是否被破坏；
- 图像是否因模糊、空白或主体消失而使内部评分降低。

主要观察量是“在最终结果确有差异的候选对中，内部选择有多常正确”，以及包括所有候选对的最终擦除/误伤结果。两者分母分别报告；不能通过删掉难以排序的候选对夸大能力。

用一部分完全未参与选择的重噪种子和审核模板再打分，检查在线分数是否只适配了固定 probe。

### 1.4 预先规定继续与停止的依据

下列是研究决策条件，不是已观察到的结论：

- 若端点上的残差比较都不能区分目标/近邻，先判定评分机制不成立；不急于增加在线 rollout。
- 若端点识别有效，但中间估计不可用，先报告时间区间边界；只对可用区间研究部署，不声称全时段有效。
- 若能识别概念，却不能优于随机或固定规则选择纠正候选，则停止把它作为候选选择机制。
- 若只对开发模板有效，或只偏好主体消失/低质量候选，停止扩展主方法。
- 若固定纠正已达到相同擦除/保留权衡，且自检在同预算下无收益，则保留诊断结论，不把更多组件当作默认补救。

使用按提示重采样的配对 bootstrap 给出不确定性。多种子属于同提示下的重复观测，不能全当作独立提示放大样本量。

## 2. 第二阶段：最小算法比较

### 2.1 必要对照

| 对照 | 要排除的解释 |
| --- | --- |
| 原模型 | 原始概念生成率与正常能力 |
| 固定 `λ` 的完整差分引导，使用相同检查步 | 自检是否优于直接加同一方向 |
| DVE 在线完整版 | 最直接的输出速度投影基线 |
| DVE 预缓存版、前中期版 | 是否只是在利用已有的计算/时间优化 |
| 安全参照中心化的投影 | 是否简单改投影基准就能获得同样收益 |
| Semantic Steering | 内部表征方法在相同模型上的效果/成本参照 |
| Steering Fields | 是否普通多条件吸引/排斥组合已经足够 |
| 主方案：新状态重新预测＋独立重噪检查 | 完整待验证机制 |

如果资源有限，第一批至少完成原模型、固定差分、DVE 在线、中心化投影和主方案；其余在核心诊断通过后加入。论文比较时仍应包含两篇指定的重点方法。

### 2.2 一个不能省略的自适应强对照

在同一当前状态，直接计算目标/安全 velocity 相对用户 velocity 的残差差，进行门控；再比较独立重噪检查。

该对照便宜、与投影密切相关。若它已经获得相同收益，就没有证据说明候选后果自检值得付出额外前向。

### 2.3 防止额外算力成为全部解释

同时给出两个视角：

1. **相同正常采样网格**：同种子、同基础步数，比较效果与全部额外成本。
2. **相同总预算**：给固定差分和 DVE 相近总查询量/实测时间，用于更多采样步、不同纠正步数或更密集纠正；调参只用开发集。

不通过让 baseline 额外做无用前向来“凑相同计算量”。还应比较随机纠正位置、固定纠正次数，以及在开发集优化好的静态 schedule，区分状态反馈与静态调度。

外部 CFG 需统计实际条件/无条件样本前向；单次 batch 调用数另报。记录在线 DiT 查询、文本编码、预处理、VAE、外部评价器耗时，不能把离线评价器算作在线主算法的依赖，也不能把在线 verifier 的耗时漏掉。

## 3. 第三阶段：必要消融

| 消融 | 要验证的问题 |
| --- | --- |
| 去掉候选新状态下的原提示重新预测 | 单纯评估当前修改，是否已经足够 |
| 去掉独立重噪，改为同状态残差 | 方法是否退化为一个重新参数化的投影 gate |
| 用候选 clean estimate 的直接速度几何分数替代重噪分数 | 改善来自新状态还是重噪的条件重建比较 |
| 两候选使用独立噪声，而非共享噪声 | 共享随机数能否改善比较稳定性 |
| `ρ=0.3/0.5/0.7`，一个或两个重噪样本 | 噪声水平与查询量的真实权衡 |
| `K=4/8/12` 个检查步 | 纠正次数与自检成本是否相称 |
| 两候选 vs 三候选 | 额外强度搜索是否值得；三候选不是默认主方案 |
| 换独立审核模板与随机种子 | 是否存在对固定 probe 的适配 |
| 自检使用 raw 条件预测 vs CFG 合成预测 | guidance 是否破坏残差含义 |
| 用相同自检规则筛选 DVE 方向 | 收益是否能跨纠正算子复用，而非依赖特定差分 |

按诊断结果开展消融，不在首轮把整张表展开成全组合网格。

## 4. 模型迁移：验证架构独立性

| 模型 | 角色 | 应特别记录 |
| --- | --- | --- |
| SD3.5-medium | 原始条件场/CFG 分离的机制诊断 | raw 条件输出、自检参数与生成 guidance 分开 |
| FLUX.1-dev | 复现 DVE 主实验模型并检验 guidance distillation 影响 | dev 的 guidance 输入、512/1024 分辨率差异、蒸馏分数校准 |
| Lumina-Image 2.0 | 统一 single-stream 结构上的输出接口迁移 | 原生 sampler 符号、时间映射、latent 标度、原概念覆盖率 |

第三模型使用其原生文本编码器，不启用额外 captioner/提示改写。将 latent packing、时间映射、输出转换放入适配层；方法内部不出现 block 索引、attention head 或模态分支名称。

区别两种迁移结果：只改接口并重校准少数标量，是方法迁移；连数值阈值都不改，是更强的零校准迁移。后者可以加测，但不作为架构无关定义的必要条件。

先在原模型确实生成得出的共享概念上比较，再给各模型扩展概念集。原模型不认识某个目标，不能把低目标生成率记作擦除成功。

## 5. 论文正式任务与评价

### 5.1 任务

主任务至少包括对象子类或角色、艺术风格，以及一类安全属性。人物身份匿名化可以扩展，但要明确保留姿态/服饰与移除身份的评价标准。

对象“删除”“替换为一般对象”“去掉特定子类特征”单独定义。比如 `church→building` 是擦除特定类别、允许保留建筑结构，不等于让图中所有建筑消失。

### 5.2 数据

复用两篇重点论文的任务定义与公开提示集，另用预留人工模板构造困难近邻、隐式描述、多对象和复杂关系提示。普通场景可用 COCO captions；小规模开发验证不叫“COCO-30K FID”。

攻击评价包括现有 I2P、Ring-A-Bell、MMA-Diffusion、P4D/UnlearnDiff 等可用提示或迁移攻击，并明确这些数据的任务属性与来源。**固定攻击提示的迁移效果与针对当前完整防护流程重新优化的自适应攻击分开报告。**

还需测试未包含显式目标词的提示、组合描述和多语言描述。测试与阈值/模板开发严格拆分，不能看过攻击测试结果再修改 probe 后仍称零样本鲁棒。

### 5.3 指标

| 维度 | 指标与注意事项 |
| --- | --- |
| 目标擦除 | 外部独立评测器的目标出现率/攻击成功率，配合人工抽查；始终报告原模型目标出现率 |
| 样本条件擦除 | 在原模型确实生成目标的配对样本中统计擦除率，并同时报告全量分母 |
| 近邻保留 | 相近但不应擦除的对象、风格、人物属性的生成成功率 |
| 场景保留 | 对象数量、属性、关系、背景的人工/独立评测；不只看全图文本相似度 |
| 通用生成 | 足量 COCO 提示的 FID/CLIPScore；小样本先报告配对质量与明显退化率 |
| 质量与多样性 | 同提示多种子多样性、低质量/空白率、人工配对偏好 |
| 效率 | 预处理成本、实际 NFE、秒/图、峰值显存、缓存体积 |
| 自检有效性 | 候选排序准确性、误接受/误拒绝、评分变化与实际概念变化的一致性 |

CLIP、NudeNet、身份/对象评测器只在离线评价使用，算法不通过它们决定在线纠正。方法内评分不能同时充当唯一最终指标。也不能把全提示 CLIPScore 的下降全部解释为质量退化：提示本身包含要求擦除的概念，需要另评应保留语义。

### 5.4 展示方式

正文最需要的不是复杂定理，而是四类图表：

1. 即时投影、自检评分、真实概念残留随采样过程的对应关系；
2. 擦除强度—近邻保留/质量的权衡曲线；
3. 相同查询预算下的效果，以及效果—秒/图曲线；
4. 同种子成功、失败案例，标出实际接受的速度纠正步，展示主体消失和概念恢复等失败。

独立检查后的最终样本由正常 sampler 产生，不对最终图做替换、挑选或重生成后只展示最佳结果。

## 6. 开发配置与论文主张分开记录

初始配置可用 30 个基础采样步、8 个检查点、两个候选、一个 probe 对、一个重噪样本，检查点先均匀覆盖实际噪声系数 `s≈0.8…0.3`。这是起点，不是论文结果或推荐最优值。按实际网格取最近且不重复的步；最后一步不做需要 `s_next>0` 的检查。

`λ_ref` 先在开发集上的 `{0.5,1,2}` 选择；`ρ` 从 `{0.3,0.5,0.7}` 选择。`θ,m` 按开发集候选选择表现校准。不要为了“少量标量”而隐藏网格评估的生成量与研究开销；所有方法使用可比的调参预算。

主算法零参数更新。若后续将自检结果压缩为少量时间段系数，应另列“少量训练/校准扩展”，披露数据、优化与参数量，并在未见概念上评价，不能替换掉未经验证的 train-free 主方案。
