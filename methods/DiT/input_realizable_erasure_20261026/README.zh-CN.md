# 面向 flow matching DiT 的输入端概念擦除：独立方法构想

日期：2026-10-26（北京时间）。本轮只以当前需求、`papers/` 中的论文原文及补充核对的一手来源为依据，没有沿用 `methods/DiT/` 其他方案或其他对话的结论。

## 建议先做什么

优先验证 **输入可实现的差分擦除**，暂用英文名 **Input-Realizable Differential Erasure，IRDE**。这是研究提案，尚未进行真实 DiT 实验；名称也不代表已确认原创性。

一句话：**先让冻结的 flow DiT 告诉我们需要怎样的速度修正，再用少量真实前向，找出能产生相近修正的文本条件修改；生成时实际使用修改后的条件。**

它从两篇重点论文分别取一个出发点：

- Semantic Steering 说明成对语义差可以提供有用的干预方向，但其方向位于 DiT 内部，不能直接当作原生文本编码器输出空间的方向。
- DVE 提供速度场中的擦除目标，但主方法不直接修改速度输出，而是尝试通过输入实现这个目标。DVE 已有缓存与早期纠正版本，必须一起比较。

最值得研究的不是“文本向量也能相减”，而是：**速度场中一个有效的擦除操作，有多少能通过小幅输入修改实现？这种限制会改善保留能力，还是只会削弱擦除？**

## 与本次要求的对应

| 要求 | 本方案的落实方式 | 仍需验证的部分 |
| --- | --- | --- |
| 优先 flow matching DiT | 用实际条件速度响应定义和检验输入修改 | 蒸馏、少步模型的响应与成本可能不同 |
| 尽量不依赖具体 DiT 结构 | 只接触原生文本条件接口和最终速度输出 | 各模型仍需处理输入格式、guidance 与时间方向 |
| 优先输入端 | 编辑文本编码器输出的条件张量，冻结编码器与 DiT | 小幅条件修改是否有足够控制能力 |
| 无训练或少量准备 | 主版本无模型训练，只预计算少量文本方向，在线拟合几个系数 | 有额外前向和小规模数值求解，不能称为零优化、零开销 |
| 少依赖外部组件 | 使用原模型、原生文本编码器与 tokenizer | 外部评估器只用于离线评估，绝不进入生成回路 |
| 数学与工程平衡 | 成对方向、有限差分、小规模拟合、真实前向检查 | 局部近似和跨步复用都作为实验问题处理 |

## 当前判断

这个方向值得做一轮有限预算的机制实验。它同时符合输入端、少训练和结构依赖弱的偏好，也有一个可以失败的清晰假设。

但它目前还不足以直接宣称为成熟论文贡献：有限差分和最小二乘都是通用工具；若实验只证明“较便宜地近似 DVE”，贡献可能只是工程实现。需要进一步证明输入约束带来的保留优势，或者跨不同 DiT 结构的稳定效果。

若少量输入方向无法实现擦除，先如实记录这一边界。不要通过增加大量方向、检查点、外部模型或逐步速度回退，把原问题改造成另一个高成本方法。
