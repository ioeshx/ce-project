# 最小实验：先验证响应，再验证擦除

日期：2026-10-27。状态：**2026-10-29 方法已被用户否决，本实验计划停止推进。** 以下为历史计划，尚未执行。

## 1. 第一轮范围

先做一个风格概念和一个具体对象／角色概念，每类选一个目标；随后有信号再扩展身份与裸露擦除。广泛安全概念不适合用来掩盖初始机制是否成立。

主模型先使用项目已有配置的 FLUX.1-dev、普通 Euler 和固定原生 guidance。第一轮固定分辨率与时间表，不同时搜索多种 solver。两个检查位置从生成前中段的三个候选位置组合中，在开发集选择；最终位置、对应 sigma、实际步长和全部开发预算都要记录。

每概念可从 8 条人工上下文、每条 2 个 seed 的开发集开始。上下文中同时包含单目标、共存对象与复杂背景。测试至少使用新上下文、新 seed，并单独加入不出现目标名称的描述；不在测试图上选强度、anchor 或位置。

“Snoopy→普通卡通狗”是角色匿名化；“狗→无狗”是对象删除。先固定任务，再确定评价标准，不能用成功替换冒充整个类别删除。

## 2. 阶段一：响应偏差是否值得处理

先只实现无修改、基础差分与响应记录。每条诊断轨迹只在一个位置干预，然后关闭后续擦除，一直采到终点。

记录 `delta0`、`b`、`R0`，分开统计：

- `||R0||/||delta0||`：响应幅度变化。
- `cos(R0,delta0)`：响应方向变化，零范数单独记。
- `||R0-b||/||b||`：相对参照的误差；参照接近零时单独记，不能用巨大比值左右均值。
- 目标残留、非目标内容保留、图像损坏，以及它们与响应误差的关系。

完整图像由独立评估决定。可以先做盲人工对比并用现有 benchmark 指标复查；评估器不参与生成或接受规则。不要把拟合误差自己既当优化目标又当唯一成功指标。

同时保存短续程与完整终点。如果短程内部差别很大、最终结果却一致，说明这项代理缺乏实际价值；如果目标恢复与原 gate 不触发相关，不能归功或归咎于响应校正。

## 3. 阶段二：最关键的标量对照

在相同状态、相同 `q0`、相同 `b` 和同一接受规则下比较：

| 变体 | 目的 |
|---|---|
| 基础候选 `delta0` | 关闭补偿的直接参照 |
| 完整补偿 `delta1` | 检验一次全维响应修正 |
| 标量响应匹配 | 检验收益是否只是更合适的强度；使用同样一次额外未来前向复查 |
| 与 `delta1` 同范数的原方向 | 排除总位移增大带来的收益 |
| 同范数、打乱方向的补偿 | 排除一般扰动或额外噪声带来的收益 |
| `b=delta0` | 检验两步条件参照是否优于保持初始位移这一更简单选择 |
| 不做真实复查 | 测量一次校正的失败率与接受步骤的贡献 |

标量响应匹配先在局部近似下取

\[
\alpha=\operatorname{clip}\!\left(
\frac{\langle R_0,b\rangle}{\|R_0\|^2},0,2\right),
\qquad \delta_{\rm scale}=\alpha\delta_0.
\]

然后真实计算 `R(delta_scale)`，按与主算法相同的规则，在它与 `delta0` 之间选一个。`R0` 接近零时使用固定基础候选。这个对照与主方法共享已完成的查询，并各增加一次候选未来前向，因而真正具有相同预算。

范数匹配对照为 `delta_norm=(||delta1||/||delta0||)*delta0`；它也需要真实复查。标量拟合、范数匹配、随机扰动是不同实验，不在单次生成中把全部候选都测完后挑最好。

打乱使用事先固定的 seed／prompt 配对或同范数随机向量；不得看到最终图像后选择最差扰动。残差总位移裁剪到 `||delta0||` 的版本只作方向修正消融，它本身无法补偿纯平行收缩。

## 4. 阶段三：完整推理与成本对照

第一轮只用两个不相邻检查点。比较以下方法的强度曲线，而非仅给单点最好值：

1. 原模型。
2. DVE 实时版、缓存版、前期纠正版。
3. Semantic Steering，使用其合理的模型设置与独立开发预算。
4. Steering Fields。
5. 基础差分在同两个检查点启用。
6. 基础差分把额外计算用在更多检查点，做到相当总 NFE。
7. 同预算标量响应匹配。
8. SCRM。

比较相近擦除率下的保留与延迟，以及相近保留水平下的残留率。对有同结构可靠实现的高阶 solver，再做一个预算对照，排除只是额外积分计算带来的效果；首轮不为此重写多种 sampler。

每张图记录底层样本前向数、批处理次数、触发率、候选接受率、峰值显存和实际延迟。模型加载、文本编码、预热与采样计时分别注明。不能把 batch=多个样本的一次函数调用记作一次样本 NFE。

单分支 `T=28`、两个完整点的理论数为 42 次，复用下一步速度后为 40 次；真实 CFG 相应为 80 或 76 次底层样本前向。门控不触发时调用数会改变，按实测汇总。小开发集的生成量也计入方法准备成本。

## 5. 擦除、保留与恢复应分别评价

擦除测试至少区分：直接目标词、同义／描述性提示、共存对象、复杂上下文、已有可用的攻击提示。先只宣称在实际测试范围内有效，不把少量无恢复样本外推成无法恢复。

保留集同时包含语义近邻、其他风格／角色、背景构图、普通人像与无关场景。背景不同不自动表示失败，也不能只凭整个图的 CLIP 相似度代表目标之外的语义被保留。共存场景应逐项检查应保留的对象、属性和关系。

小规模机制实验优先采用同 seed 配对、盲评和样本级结果；报告失败图。若进入完整评测，再使用项目已有 COCO 等协议。几十张机制图不报告为稳定 FID 结论。

恢复实验包括：单次脉冲后关闭擦除、两点完整策略、在两个点之间继续原提示、不同 guidance。代理改善与最终残留的相关性按新 prompt／seed 复验，不能只分析开发集。

## 6. 架构迁移的证据要求

有主模型信号后，再迁移到 SD3.5 的 flow DiT，以及一个**真正不同组织方式的单流 flow DiT**。模型选择需要核对公开训练说明与可用 checkpoint；FLUX 自身同时包含双流／单流 blocks，不能仅凭在 FLUX 与 SD3.5 上成功就证明纯单流迁移。

可考虑官方 [Z-Image](https://github.com/Tongyi-MAI/Z-Image) 的合适变体，具体基座／蒸馏状态在实施时锁定。其原生 Qwen 文本编码器属于生成系统，不等于额外接入 Qwen VLM 判别器。

允许每个模型独立开发基础强度与检查位置。保持相同计算链，不给某个模型额外增加内部 hook。报告接口迁移是否只涉及时间、格式和原生 guidance；若必须新增架构专属模块，应降低“架构无关”的表述。

少步 guidance-distilled 模型属于进一步测试：两个检查点可能已占大半轨迹，开销比例也明显不同，不把普通 28 步结果直接外推。

## 7. 何时继续，何时停止

继续所需的证据是：

- 两步响应偏差具有可重复的最终图像意义，而非仅 L2 差别。
- 全维补偿在相同预算下优于标量响应拟合、范数匹配和同强度基础差分。
- 收益存在于未见上下文／seed，并在多个概念上复现。
- 在相当擦除／保留水平下仍有可接受的实际延迟与显存。

以下情况应收缩或放弃主张：

- 仅比基础候选好，但不优于同预算标量对照：定位为自适应强度改进。
- `b=delta0` 与两步参照同样好：去掉概念分支的第二步计算，按更简单方法重新评价。
- 响应误差下降，图像残留或保留无改善：局部代理不成立，停止追加模块。
- 一定要逐步运行、多次迭代或加入外部安全模型才能有效：不再符合当前方法的预算与依赖偏好。
- 只有一个概念／模型有效：报告具体边界，不宣称通用擦除。

当前已完成的是方法逻辑与调用数核对；二维手算例子检查过数值。上述 GPU 机制实验、完整采样、性能评测和跨架构验证均未运行。
