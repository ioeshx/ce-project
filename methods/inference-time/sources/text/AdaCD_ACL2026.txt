B    Baseline Implementation Details :
We re-implemented SSD, Surgical, and Self-CD, and compared them with our approach using their
publicly available code. It should be noted that SSD employs an additional expert model (which is also a
draft model) for speculative decoding. However, the authors of SSD did not provide the expert models for
Gemma2 and Qwen3. Therefore, we fine-tuned Qwen3-4B and Gemma2-2B as expert models following
the training settings provided by the authors. For the Default methods, we directly used the open-source
Llama3, Gemma2, and Qwen3 models. Importantly, all algorithmic hyperparameters were set to the
default values recommended by the authors to ensure fairness. For the Prompt baseline, we also used the
system prompts designed in their paper to reproduce the results. To ensure a fair comparison, all methods
are evaluated on the same computing device equipped with three NVIDIA RTX A6000 GPUs.

C    GPT-4 Evaluation Results
To provide a more comprehensive comparison of AdaCD’s performance, we used prompted GPT-4 as the
evaluator to determine whether it refused to answer over-refusal queries and avoided generating harmful
content for malicious queries. Experiments were conducted using Qwen3 model on the XSTest-Safe
and XSTest-Unsafe datasets, and refusal ratio were calculated following the GPT-4 template provided
in Appendix E of (Dabas et al., 2025). The results are shown in Figure 6. It can be observed that in
over-refusal scenarios, the evaluation results based on GPT-4 show a slight decline compared to those
obtained with WildGuard. However, AdaCD consistently maintains the lowest refusal rate across all
over-refusal scenarios. At the same time, in malicious scenarios, only AdaCD can guarantee a 100%
refusal ratio. This further validates the conclusion in Section 4.2 that AdaCD can mitigate over-refusals
while maintaining model safety.

D    Additional Ablation Study

D.1 Ablation Analysis of α

We conduct the further ablation analysis on the hyperparameters α of AdaCD. The experiments are
performed using the Llama3 model. To investigate the effects of α, we set α = 3.5, 4.0, 4.5, 5.0. Figure
7 illustrates the influence of α on the refusal ratio under over-refusal and malicious scenarios. It can be
observed that as α increases, the regulatory effect of the refusal token distribution on AdaCD gradually
strengthens, leading to a consistent decrease in the refusal ratio for over-refusal scenario. As a contrast,
in the malicious scenario, as the hyperparameter α increases, the model’s regulatory effect on potential
refusal tokens gradually strengthens, resulting in an initial rise in the refusal ratio. However, when α
becomes too large, the overly strong regulation may induce certain output shifts, causing the model to
produce more neutral responses to malicious prompts, which in turn leads to a decrease in the refusal
ratio. This phenomenon is consistent with the observations reported in (Shi et al., 2024). Therefore, when
α = 4.5, AdaCD achieves an optimal balance, keeping refusal ratio high on malicious queries while
reducing over-refusals.

D.2 Full Results of Ablation Switch Mechanism
We separately evaluate the refusal ratio using only the adaptive confidence threshold (w/o AGR), or using
only the agreement ratio (w/o ACC) as the decoding mode switch strategy. The refusal ratio of different
models on ORBench, OKTest, AdvBench, and JailBench are presented in Table 9. As shown in the
table, removing either mechanism leads to an increase in refusal ratio under over-refusal scenarios and a
decrease in refusal ratio under malicious scenarios, further demonstrating the effectiveness of AdaCD’s
adaptive decoding mode switch strategy. Specifically, removing the adaptive confidence threshold, i.e.,
w/o ACC, results in larger changes in refusal ratio compared to removing the agreement ratio. However,
AdaCD achieves optimal performance only when both mechanisms work in synergy.

E.1    Adaptive Plausibility Constraint Parameter β
Following (Li et al., 2023), AdaCD also adopts the Adaptive Plausibility Constraint to prevent the model
from generating grammatically incorrect outputs. Specifically, AdaCD selects the next token only from a
confidence-filtered candidate token set W, which is defined as:
                                                                               
                      W = yn ∈ V Pπ (yn | x, y<n ) ≥ β · max Pπ (y | x, y<n ) .
                                                                   y∈V

where V denotes the vocabulary of the model. As described in Section 3.1, when facing over-refusal
scenarios, our objective is to filter out low-probability non-refusal tokens from the candidate list. Therefore,
we set β to 0.01 instead of the default value of 0.1 used in (Li et al., 2023). To investigate the impact
of the parameter β on AdaCD, we vary β among 0, 0.01, 0.05, and the default value of 0.1. Table 10
reports the refusal ratios of AdaCD under different β settings. When β is set to 0, the Adaptive Plausibility
Constraint is removed. As shown in Table 10, except for the case of β = 0, increasing β consistently
leads to higher refusal ratios in both over-refusal and malicious scenarios. For β = 0, we observe that the
model frequently generates grammatically incorrect outputs, making the evaluation results unreliable. To
provide a more intuitive analysis, we present three representative examples in Table 11 to illustrate this
issue. Notably, this phenomenon also exposes a drawback in the recent work (Shi et al., 2024).

H Algorithm Workflow
To provide a clearer understanding of AdaCD, we present the pseudo-code in Algorithm 1. Overall, our
AdaCD is training-free, requiring no modification of model parameters, and model-agnostic, directly
altering the output distribution without changing the model’s architecture. For a given user query x, we
first initialize x as the initial sequence (Alg. 1, line 1). Next, a forward pass is performed on both the
model with the extreme system prompt p∗ and the model without any system prompt (Alg. 1, line 4 &
                                                         39322
line 6). Within the specified range of contrastive decoding steps k, the top-1 token yn∗ is obtained from
the model with the extreme system prompt (Alg. 1, line 8), and the agreement ratio agr(n) is computed
(Alg. 1, line 10). Based on the difference between token distributions, the refusal token distribution is
then extracted (Alg. 1, line 12). The maximum probability ρ in the model’s current token distribution
is compared with the adaptive confidence threshold λ · ρ∗ (Alg. 1, line 14 - line 15). If agr(n) ≥ λ
and ρ ≥ λ · ρ∗ , the refusal token distribution is added to the current token distribution to increase the
probability of selecting refusal tokens; otherwise, it is subtracted to suppress the probability of selecting
refusal tokens (Alg. 1, line 16 - line 20). Finally, for the remaining N − k tokens, standard decoding is
used to generate the rest output (Alg. 1, line 24).

    Algorithm 1: Adaptive Contrastive Decoding (AdaCD)
     Input: User query x, extreme system prompt p∗ , contrastive steps k,
            hyperparameters α, λ, max new token number N
     Output: Generated sequence y
 1   y ← x;
 2   for n ← 1 to N do
 3       // Forward passes
 4       Pπ (yn |x, y<n ) ← σ(fπ (yn | x, y<n ));
 5       if n ≤ k then
 6           Pπ (yn |p∗ , x, y<n ) ← σ(fπ (yn | p∗ , x, y<n ));
 7           // Calculate Agreement Ratio 
 8           yn∗ ← arg maxyn Pπ (yn |p∗ , x, y<n ) ;
 9           rank ← The index of yn∗ in sorted Pπ (yn |x, y<n );
10           agr(n) ← 1/rank;
11           // Refusal Token Distribution Extracting
12           ∆Pn ← σ(fπ (yn | p∗ , x, y<n ) − fπ (yn | x, y<n ));
13           // Adaptive Decoding Mode Switch
14           ρ ← maxyn Pπ (yn | x, y<n );
15           ρ∗ ← Pπ (yn∗ | p∗ , x, y<n );
16           if agr(n) ≥ λ and ρ ≥ λ · ρ∗ then
17               Pπ∗ (yn | x, y<n ) ← Pπ (yn |p∗ , x, y<n )) + α · ∆Pn ;
18           else
19               Pπ∗ (yn | x, y<n ) ← Pπ (yn |p∗ , x, y<n ) − α · ∆Pn ;
20           end
21           yn ← arg maxyn Pπ∗ (yn | x, y<n );
22       else
23           // Fall back to standard decoding   
24           yn ← arg maxyn Pπ (yn |x, y<n ) ;
25       end
26       Update sequence y ← y ∪ {yn };
27   end
28   return y;
