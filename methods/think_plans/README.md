# ConceptAttention 引导的概念擦除：评估与五套方法方案

日期：2026-11-04。本文档组交付研究设计、算法和实验方案；尚未运行这些新方案的模型实验。

## 先回答当前最重要的两个问题

**“概念分支定位＋安全表示 patching”可以做，但仅凭这两项操作，与已有工作的差别还不足以构成强贡献。** UVR 已明确借鉴 ConceptAttention 的 attention 输出空间定位；NLCE 已有同一步两次前向和跨层共享 gate；PER 已有检测后 patch 替换；FOMO 已有输出空间定位和局部安全表示对齐。真正需要研究的是：定位何时可靠、供体是否与当前场景匹配、在哪里干预才有效、如何保留同区域的其他内容，以及后续生成是否恢复目标。

**工作点的数量不是方法完整性的标准。** 一个新增机制若能解决上述明确问题，并在相同预算下改善擦除—保留关系，就比再叠加若干常规模块更有价值。下面五套方案分别围绕一个中心问题展开，均包含定位、patching 和一个承担实际任务的新增机制。

## 如何选择，而不是把五套全部堆在一起

| 方案 | 核心研究变量 | 定位外新增的机制 | 建议定位 |
| --- | --- | --- | --- |
| 一 | 目标存在证据与层间一致性 | 负例校准、空目标拒绝 | 最小可实现版本；单独作为论文主线的增量偏小 |
| 二 | 当前样本需要什么安全内容 | 场景条件供体、空间匹配和匹配失败回退 | 若直接供体替换明显改变结构，优先研究 |
| 三 | 哪些层／时间真的影响最终目标 | 离线配对干预、预算内位置选择 | 最建议作为主线之一；前提是实测存在选择性有效位置 |
| 四 | 一个区域内哪些通道应保留 | 约束优化、可行性判断、多概念联合求解 | 与原算法差别清楚，适合数学与实证并重的主线 |
| 五 | 编辑后的目标是否重新出现 | 跨步监测、滞回触发、有界强度控制 | 若实验观察到明显重现，适合作为第三项主要机制 |

**建议的起步路线：先实现方案一作为共同底座，在小样本上检查供体错位、干预位置和后续重现，再选择二、三、四、五中的一个作为主研究问题。** 在没有测到对应问题以前，不需要同时引入传输、子空间和时序控制。

若必须先选一套完整主方法，建议选方案三：使用明确的概念证据形成统一空间掩码，按最终生成的擦除／保留响应选择少量干预位置，再执行同状态安全 patching。若少数位置的干预响应并不优于末层或全层，转而研究方案二或四。

## 与现有工程的关系

当前 [attention replacement](../../DiT/attention_replacement/README.md) 已有 `layerwise`、`majority_all`、`majority_last`，距离掩码和离线 anchor 均值可以保留为基线。本组方案新增的是研究设计，不修改这些实现，也不将现有距离投票视为已经实现 ConceptAttention。

一个执行成本上的修正：**全层读出后只在最后位置 patch，不必总是再完整运行一次用户前向。** 当掩码所需信息在 patch 点已齐备时，可以当场替换；否则缓存用户前缀状态，仅重放该点之后的后缀。需要在更早层应用全层掩码时，才必须重放受干预影响的前向部分。精确条件见共用算法文档第 5 节。
