# 方案五：目标重现感知的时序闭环替换

## 1. 动机与中心问题

末层 patch 可以改变当前预测，但下一采样步仍受原 user prompt 驱动，目标可能重新形成。另一方面，若目标已经消失，持续按固定窗口替换会浪费 donor 计算并增加非目标变化。

本方案研究：**能否只在有当前目标证据或确实观察到重现时干预，并在有限修改预算内维持擦除？**

完整方法为概念分支定位、同状态末层 patching，以及**逐步重新观测的重现检测、滞回触发和有界强度控制**。在线监测使用正常下一采样步的 probe，不为每个候选运行多步未来 rollout。

## 2. 监测分数与两类概念查询

定位使用 `C_loc`，包含目标、安全和保留概念。另固定一小组不用于 donor 构造的目标描述 `C_mon`，作为监测读出，例如同一目标的另一种视觉描述。两组均在开发集确定，部署时不根据结果挑词。

每步从当前实际 `x_n` 做未编辑 user＋concept probe。按噪声区间标准化后，定义：

\[
R_n=\operatorname{TopKMean}_i
\sum_{\ell\in L_{loc}}\omega_\ell
z^{mon}_{n,\ell}(i).
\tag{1}
\]

`z^mon` 由监测概念相对于安全／背景的对比读出得到。它与定位分数共享主干，仍可能具有共同盲点；最终评价使用独立的图像评估器。

采用下一实际采样步重新计算的概念向量，而不是固定旧方向评估刚刚执行的同向投影，避免把代数上必然下降误认为后续擦除已经成功。

## 3. 滞回触发与空间掩码

设置 `theta_off < theta_on`。若系统当前未激活，仅在 `R_n>theta_on` 时开启；已激活时，在连续 `q` 个监测步均低于 `theta_off` 后关闭。这两个阈值和 `q` 在开发／校准数据上固定。

定义局部定位分数 `r_n(i)`，其开关阈值为 `tau_off<tau_on`。在激活状态下：

\[
M_n(i)=G_n\left(
\mathbf1[r_n(i)>\tau_{on}]
\lor
\left[\mathcal D_r(M_{n-1})(i)
\land\mathbf1[r_n(i)>\tau_{off}]\right]
\right).
\tag{2}
\]

`D_r` 是有限半径膨胀。旧位置必须仍有当前证据，不能把历史掩码永久取并集。新位置可以凭较强证据直接进入；膨胀只容许有限移动，不把同一 token 索引当作物理目标跟踪保证。

首轮比较无历史掩码、纯 EMA 和式（2），只有实测抖动时才保留空间滞回。

## 4. 区分持续残留与真正重现

记录两种事件：

- **持续残留**：编辑后，后续若干步的 `R_n` 一直没有降到关闭阈值以下；
- **重现**：已经编辑过，随后至少 `q` 个监测步低于关闭阈值，之后又超过开启阈值。

令 `b_n` 为第二种事件的指示量。这个定义依据离散监测读出，不等价于最终图像在每个中间时刻已经可确认安全。

统计重现时，记录实际噪声水平、距上次编辑的步数和目标区域移动；不能仅因分数下降后小幅回升就计为重现。

## 5. 有界强度控制与修改预算

控制器使用签名误差：

\[
e_n=R_n-R_*,
\tag{3}
\]

并产生期望强度：

\[
\eta_n^{want}=\operatorname{clip}_{[0,\eta_{max}]}
\left((1-\gamma\mathbf1[\text{quiet}_n])\eta_{n-1}
+k_R e_n+k_B b_n\right).
\tag{4}
\]

`quiet_n` 表示本步低于关闭阈值；初次触发时给一个开发集确定的最小启动强度。`eta_max<=1`。式（4）是待验证的有限状态反馈规则，不提供一般闭环稳定性定理；需要与固定强度、只随时间变化的 schedule 和仅风险比例控制比较。

`R_*` 是预设的低风险参考值，取不高于 `theta_off`；`k_R,k_B>=0`，`0<=gamma<1`。初始历史掩码为空，尚未发生编辑时不计重现。默认监测窗口覆盖全部采样步，供体与 patch 由触发状态决定；若缩短监测窗口，窗口外不再声称具有重现监测能力。

每个候选强度执行末层 blend：

\[
O'_i=O_i+\eta M_n(i)(O_i^- -O_i).
\tag{5}
\]

重放较短后缀即可得到候选 prediction。缓存的未编辑 prediction 记为 `v_n^0`，完成原生 CFG 后的候选记为 `v_n^eta`。定义可计量修改能量：

\[
c_n(\eta)=w_n\operatorname{Mean}
\left[(v_n^\eta-v_n^0)^2\right].
\tag{6}
\]

普通比较取 `w_n=1`；原生 Euler flow 更新时，可取实际步长平方 `w_n=h_n^2`，对应本步 latent 改变量的均方。其他 solver 需按其真实更新定义权重，不能随意套 Euler 公式。

维护总预算：

\[
B_n=B_0-\sum_{j<n}c_j(\eta_j).
\tag{7}
\]

从 `eta_n^want` 起，最多做固定次数的减半回退，选择满足 `c_n(eta)<=B_n` 的强度。预算不足则本步不编辑并记录未解决目标证据。这里限制的是计算中的修改能量，不等于给最终图像质量提供上界。

不要对多个候选各调用一次真实 scheduler 更新；所有候选从同一缓存状态重放，scheduler 只对接受的 prediction 推进一步。

## 6. 完整执行流程

```text
初始化：G=off，quiet_count=0，eta_prev=eta_start，剩余预算 B_0
for 每个采样步 n：
    从当前 x_n 做 user＋concept probe；保存 v_n^0 和末层重放状态
    得到定位分数、监测分数 R_n；更新激活／关闭状态及重现事件 b_n
    若 G=off 或区域掩码为空：用 v_n^0 更新；降低并保存 eta_prev；continue
    用当前证据和有限历史形成 M_n
    从同一 x_n 获得完整场景 safe donor O_n^-
    按式（4）产生 eta_want
    对固定小候选集：仅重放末层后缀，计算式（6）的修改成本
    接受预算内候选；若均不满足，使用未编辑 prediction
    用接受结果推进一次 scheduler，扣减预算，保存实际 eta
    下一真实采样步重新读出目标；不把当前线性读出下降当作成功标签
```

首次触发前可以使用方案一校准的图像级阈值。首次编辑后轨迹分布已变化，不继续主张无编辑校准数据提供同样的逐步统计保证。

## 7. 成本与部署资源

user＋concept probe 覆盖监测窗口中的每一步。只有需要编辑的步才运行 safe donor。设每个启用步平均尝试 `J_n` 个强度、末层后缀比例为 `rho_n`，额外等价成本为：

\[
K_{edit}+\sum_{n\in E}J_n\rho_n
\tag{8}
\]

再加定位／监测概念分支成本。没有额外完整模型 lookahead；若 patch 点提前，`rho_n` 增大，必须重新测量控制候选的成本。

预算参数和阈值按模型、采样器和 guidance 配置校准。多目标维护各自的触发状态，共享一次 user probe；不同 safe prompt 仍可能需要多个 donor 前向，不能把共享监测当作供体成本也与目标数无关。

## 8. 与已有工作的差别

[UVR](https://arxiv.org/html/2606.06875) 已分析危险语义在不同阶段的传播与恢复；[Concept Corrector](https://arxiv.org/html/2502.16368) 已有中间结果检查和后续纠正。因此“边生成边检查”“动态强度”不能作为新的总体思想。

本候选要验证的是：利用无需图像解码的内部多层读出，明确区分持续残留和观测到的重现，在末层短后缀可重复计算的条件下，将有限改动预算分配给确有需求的采样步。它与 Concept Corrector 使用生成图像检查／概念移除 attention 的具体路径不同，也与 UVR 的信息流缩放和噪声注入不同。

相邻方法可能已有其他反馈控制形式；进一步查新时按“内部读出、触发事件、预算定义、实际编辑变量”逐项比较，不能仅按方法名称判断区别。

## 9. 必要实验与主张

### 是否真的有重现

在固定末层 patch、固定强度和早期时间窗下，画完整轨迹的定位与监测读出；在若干固定噪声位置解码预测图供离线检查，结合最终独立评分。解码只用于实验分析，不加入在线成本优势的实现。

### 反馈是否优于固定时间表

在相同 donor 前向预算、相近擦除率下比较：固定早期窗口、固定全程弱编辑、按噪声时间预定强度、当前风险触发、完整重现反馈。报告后半程目标残留和近邻内容保留。

### 滞回与预算是否有独立价值

比较去掉空间历史、去掉 quiet 关闭、去掉重现增益和去掉能量约束。记录 mask IoU 随步变化、编辑步数、重现次数、累计能量和总延迟。

### 检测盲点

用未参与定位的监测描述降低单一读出的自我验证问题，同时由独立最终评估器判断成功。若内部风险很低但最终目标仍出现，记录为监测失败，而非成功擦除。

拟主张是“有限预算内的按需持续控制改善后续重现与过度编辑的权衡”。若固定 schedule 在相同预算下达到同样表现，就无需保留完整反馈控制器。
